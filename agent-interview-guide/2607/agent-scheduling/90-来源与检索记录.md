# 来源与检索记录

## 1. 本地源码基线

本文组逐文件核对提交 `2e463aa290a17c01eec45d229162db3952a42e6f`。39 个文件分布在 `agentPlatformShared`、`agentToolsShared` 与 `agentLangchainService`。本地源码用于说明 AlphaFrog 当前实现，官方资料用于解释通用机制，二者用途不同。

## 2. 官方资料

### 2.1 Java 有界执行器

Oracle Java API 的 [Executors](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/concurrent/Executors.html) 与 [`ThreadPoolExecutor`](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/concurrent/ThreadPoolExecutor.html) 说明了线程池、固定工作线程、任务队列和拒绝策略的基础语义。AlphaFrog 在此基础上增加运行名额、有限排队和恢复任务复用同一入口。官方资料不能证明 AlphaFrog 的实现正确，具体结论仍来自 `LangchainRunConcurrencyScheduler` 源码。

### 2.2 PostgreSQL 并发更新

PostgreSQL [官方教程](https://www.postgresql.org/docs/current/tutorial.html) 提供事务、SQL 与并发数据库的基础背景，[Transaction Isolation](https://www.postgresql.org/docs/current/transaction-iso.html) 说明 `Read Committed` 等隔离级别下的并发可见性。本文讨论的所有权竞争进一步依赖源码中的条件更新：调用方通过受影响行数判断 `WHERE` 中的旧状态、令牌和版本是否仍成立。

### 2.3 Redis 作为到期索引

Redis [Data store quick start](https://redis.io/docs/latest/develop/get-started/data-store/) 与 [Quick start](https://redis.io/tutorials/howtos/quick-start/) 说明了键值、过期和数据结构的基本用法。本项目把 Redis 用作近期任务与到期时间的快速索引，PostgreSQL 仍保存恢复事实。教程没有把 Redis 描述成唯一事实源。

### 2.4 持久执行的通用思路

Temporal 的 [Workflow Execution](https://docs.temporal.io/workflow-execution) 与 [Java SDK](https://docs.temporal.io/develop/java) 说明了持久执行、重放和等待外部事件时释放计算资源的通用目标。AlphaFrog 没有接入 Temporal，也没有实现 Temporal 的事件历史重放；它通过业务表 JSON 锚点、检查点、条件更新和后台扫描实现自己的恢复协议。

### 2.5 官方教程的组织方式

Spring 的 [异步方法教程](https://spring.io/guides/gs/async-method/) 和 Kubernetes 的 [基础教程](https://kubernetes.io/docs/tutorials/kubernetes-basics/) 都先说明学习目标与最终产物，再使用连续步骤推进一个可观察示例。本文组借鉴这种教学组织：先说明为什么，再跟随 `run-42` 的一次完整生命周期，最后回到逐文件职责和故障窗口。

### 2.6 工具执行器、Redis 索引与 SQL 更新结果

LangChain4j 的 [Tools 教程](https://docs.langchain4j.dev/tutorials/tools/) 说明 `ToolSpecification`、`ToolExecutor` 与 `InvocationContext` 的扩展位置。本文只使用它解释模型工具调用怎样进入 Java 执行器；AlphaFrog 的工具预算、事件、沙箱分发与检查点来自项目源码。

Redis 的 [Sorted sets 文档](https://redis.io/docs/latest/develop/data-types/sorted-sets/) 说明按分值排序与按分值范围查询。项目把下一次轮询时间写成分值，用它快速取得到期运行；恢复决定仍需重新读取 PostgreSQL。

PostgreSQL 的 [`UPDATE` 文档](https://www.postgresql.org/docs/current/sql-update.html) 说明命令返回的更新行数。项目数据库映射层以更新行数是否为一，判断带旧状态、操作身份、令牌或版本的条件更新是否取得资格。

Temporal 的 [Durable Execution 技术说明](https://assets.temporal.io/durable-execution.pdf) 用于补充进程失效、重试与持久状态的通用背景。本文没有把 Temporal 的历史重放或产品保证映射成 AlphaFrog 已完成能力。

## 3. 事实范围

以下结论属于当前源码事实：长沙箱任务会持久化锚点和检查点；挂起控制信号沿工作流向上传递；调度器包装层在 `Runnable` 返回时归还运行名额；后台完成器分步骤保存终态；恢复服务使用令牌与版本竞争启动权；恢复执行器跳过已经完成的待办节点并注入终态结果。

以下内容是通用工程解释：为什么有界队列需要背压，为什么条件更新可以表达所有权，为什么恢复租约需要版本递增，为什么结果消费要先于后续副作用持久化。这些解释由官方资料与并发系统常识支持。

以下内容是当前限制，不能表述成已经完成的保证：同一次运行顺序发生第二次长工具挂起；用户在 `WAITING_TOOL_JOB` 时暂停后的锚点处置；部分 `CAS_STATUS` 与 `LAUNCHING` 状态组合的 PostgreSQL 启动补扫；在线修复长期停留的 `PREPARING`；检查点补偿返回 `UNOWNED` 后仍拥有持久处理者；Redis 脚本和个别数据库更新结果的全面校验。
