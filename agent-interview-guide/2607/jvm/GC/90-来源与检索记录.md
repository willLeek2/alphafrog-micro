# 来源与检索记录

## 证据使用方式

本轮把资料分成三类：

1. 2024 年以来的校招、暑期实习和日常实习面经，用于确认面试官实际怎样询问。
2. 2025—2026 年 Oracle 与 OpenJDK 资料，用于校正工具用途、收集器版本和排查结论。
3. 英文面试整理站点，只用于观察问题形式，不采用其中过时答案。

公开面经属于候选人自述，无法还原完整面试过程。面经能够证明“有人记录过这种问法”，不能证明作者附带的技术答案正确，也不能保证下一次面试命中。

## 项目材料的事实范围

项目部分只进行了代码审视，没有连接线上环境，没有执行 GC 压测，也没有采集 GC 日志、JFR 或堆转储。可以陈述的业务事实是：任务列表为了计算产物标记，会逐任务进入完整产物查询；完整查询会读取历史事件、解析载荷、关联调用与数据集并构造产物。能否引起 Young GC、Full GC、巨型对象或内存泄漏，必须通过运行数据验证。

项目正文没有写源代码文件名、方法名和行号，避免把面试回答变成代码讲解，也符合“最高精确到业务逻辑层面”的要求。

## 限制

- 面经样本不是招聘公司官方题库，出现次数不等于命中概率。
- 不同 JDK 与收集器的事件名称和行为存在差异，回答 Full GC 时需要先说明版本与收集器。
- 不同容器、JDK 发行版和权限设置会影响 attach、JFR、NMT 与堆转储的可用性。
- 文档中的命令用于说明证据类型，真实环境执行前仍需评估权限、磁盘、暂停和敏感数据风险。
