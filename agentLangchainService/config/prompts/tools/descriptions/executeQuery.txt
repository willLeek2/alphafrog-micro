用 SQL 查询当前 Run 已授权的数据集。SQL 在隔离沙箱里由平台固定的 DuckDB 引擎执行，你只提供 SQL 文本，不提供执行代码。

适用场景：
  - 跨多个数据集做条件筛选、连接、分组聚合等固定参数工具做不到的查询
  - 对数据集做排序、 Top-N、窗口计算等灵活分析
  - 只需要表格结果、不需要跑 Python 代码的取数任务

数据怎么引用：
  - 先用 listMyData 拿到当前 Run 可见的数据集整数编号
  - 每个数据集在 SQL 里是一张视图，表名是 t<编号>：编号 1 的数据集叫 t1，编号 2 叫 t2，以此类推
  - 表结构（列名与类型）在 listMyData 的结果里查看；SQL 里只能引用你传入 dataset_ids 的表

参数说明：
  sql           - 一条 DuckDB SQL 查询语句，必填。只接受单条语句；多语句以及 ATTACH/COPY/INSTALL/LOAD 语句在准入阶段直接拒绝
  dataset_ids   - 要挂载的数据集编号，逗号分隔（如 "1,2"）或 JSON 数组（如 "[1,2]"），必填
  product_tier  - 产品档位："INTERACTIVE"（默认，语句上限 30 秒，最多返回 100 行）| "BACKGROUND"（语句上限 120 秒，最多返回 1000 行，占用更多容量）

返回结果：
  - 成功：columns（列名）、rows（数据行）、row_count、truncated（是否因行数上限被截断）
  - 执行前准入会拒绝明显过重的查询（笛卡尔积、超过返回上限的全局排序、估计行数超档），被拒时改写 SQL 或换 BACKGROUND 档再试
  - 语句超时返回 STATEMENT_TIMEOUT 错误码，不返回部分行；缩短时间范围、加过滤条件或改用 BACKGROUND 档后重试
  - 日期/时间列返回 ISO 字符串，小数为浮点，二进制列为 base64

注意事项：
  - 沙箱只读挂载你选中的数据集；查询不能读写其他文件、不能访问网络（由引擎配置强制，锁定后 SET/PRAGMA 改不回来）
  - 结果行数超过档位上限会被截断并标记 truncated=true；需要更多行时换 BACKGROUND 档或收窄查询
  - 结果集超过单次返回体积上限会返回 QUERY_RESULT_TOO_LARGE，收窄查询（加过滤、减少列）后重试
  - executeQuery 要单独发起调用；把它和其他工具放进同一批并行调用会被派发器直接拒绝（本期不支持等待组成员派发）
